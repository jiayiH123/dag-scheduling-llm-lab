# LLM roles for one-forward budgeted DAG scheduling

Date:2026-10-15. AI-executed primary-source/code audit; all proposed architectures and expected benefits are ai-suggested and untested. No LLM request, model download, remote connection, new training, solver call or neural evaluation was executed.

## Grounded starting point

The current model consumes a task-device product graph, with12 numerical features per pair and communication-weighted dependency edges. A single GNN call returns intercept a[i,p] and budget coefficient w[i,p]. `CachedBudgetDecoder` computes dynamic EFT and affordability, using score a+w*phi-EFT/scale, eligibility/budget reserve masks and cumulative-capacity insertion. Default order is descending HEFT rank. Main data is synthetic numerical workloads, scalar demands, fixed edge delays, fixed pools and additive task cost; there are no genuine natural-language task semantics to exploit yet.

Changing only the backbone keeps both the fixed-order reachable set and the terminal-reward problem. It might improve approximation/exploration, but cannot remove a scheduling-order restriction. Previous joint-order pilots already had negative settings, so learning priorities is not a newly discovered untouched direction.

## Primary sources and scope

- **ReEvo**, NeurIPS2024: https://proceedings.nips.cc/paper_files/paper/2024/file/4ced59d480e07d290b6f29fc8798f195-Paper-Conference.pdf ; author code https://github.com/ai4co/reevo . LLM-generated heuristic programs plus execution feedback/evolution. Code lists routing/packing/placement tasks; not a demonstrated solution to our exact hard-budget cumulative-capacity DAG model. Read documentation, did not install or execute it. The paper/code support offline heuristic design, not a guarantee that a prompted LLM directly produces better feasible schedules here.
- **EoH**, ICML2024: https://proceedings.mlr.press/v235/liu24bs.html . LLM turns heuristic thoughts into executable code and evolutionary selection; supports an offline design role, not exact-model superiority. Paper landing page read; no EoH reproduction.
- **LLMs can Schedule**, author-hosted DSO2025 workshop paper: https://www.lamsade.dauphine.fr/~cazenave/papers/LLMsCanSchedule-DSO-2025.pdf ; dataset https://github.com/starjob42/datasetjsp . Direct text-based JSSP solving and finetuning,120k generated demonstrations, solver time cap300s; paper says larger demonstrations are not all OPT. Sec.4 notes unsatisfactory zero-shot results; Sec.6 parses and validates operation/machine/timing outputs. Demonstrates feasibility of a different approach, not superiority in our graph/budget/one-forward scenario. Do not import its JSSP targets as if interchangeable with DAG pool assignments.
- **Transformers generation documentation**: https://huggingface.co/docs/transformers/v4.50.0/en/cache_explanation . Its generation loop repeatedly calls the model for next-token predictions, even with KV cache. One API request or one `generate()` is not a single backbone forward.
- **Qwen2 model interface**: https://huggingface.co/docs/transformers/model_doc/qwen2 . A forward call returns per-position hidden states and accepts inputs_embeds. This supports building a parallel structured policy head; it does not establish that the resulting policy improves scheduling.

## Structured ideation: constraints, decomposition and reformulation

Applied brainstorming F1(problem-first),F7(simplicity),F9(decomposition), plus creative F2(representation),F4(constraints),F8(one-pass capacity versus global decisions). Hard constraints: dependency/eligibility/cumulative capacity/hard total budget/common fixed communication physics/one full forward and one final schedule construction. Soft choices: fixedHEFTorder, GNN backbone, two-score functional form, fixed offline teacher recipe. Do not silently relax hard constraints to make an LLM look better.

Raw candidates, retained including rejected ones:

| ID | LLM role | Status and reason |
|---|---|---|
| L01 | Text-generate complete assignments and timestamps | Low priority: autoregressive multi-forward and feasibility/timing validation burden |
| L02 | Call LLM for each ready task decision | Reject for main objective: repeated neural processing |
| L03 | Choose one existing heuristic ID before executing it | Cheap auxiliary baseline; bounded by per-instance best of the SAME candidate/decoder set, no new solution family |
| L04 | Output instance-wide weights for cost/EFT/communication | Keep as simple macro-controller candidate; numerical small MLP is a mandatory control |
| L05 | Predict task/branch upgrade values or budget opportunity cost | Keep: soft preference, not a hard arbitrary branch budget; global reserve mask remains authoritative |
| L06 | Parallel priorities plus task-pool score heads | Best aligned direct-policy candidate, but must disentangle changed order space from backbone |
| L07 | Parallel task-pool heads with exactly the old fixed-order decoder | First clean backbone pilot; cannot solve order reachability |
| L08 | Identify communication-sensitive groups/joins | Possible auxiliary representation; GNN or algorithmic grouping may suffice, avoid an untested module pile |
| L09 | Generate dispatch-scoring heuristic programs offline | Highest low-cost offline priority; ReEvo/EoH precedent; frozen resulting code runs without LLM |
| L10 | Design coordinated remapping neighborhoods offline | Keep as teacher/search improvement; offline search work cannot be hidden as one-decode policy work |
| L11 | Diagnose failure cases/curriculum offline | Useful research support; no claim of deployed LLM scheduler |
| L12 | Generate language rationales for numeric labels | Low priority: no ground-truth rationale or evidence it helps the strict-one-forward actor |
| L13 | Predict makespan/criticality as a training auxiliary | Possible, but labels/calibration/ablation needed and an ordinary regressor is a strong control |

Top three roles:

1. Offline scoring-rule/neighborhood designer (L09/L10): direct use of language/code prior, no deployed latency, freeze rules from training/selection data and independently validate physical schedules. Any resulting strong heuristic is also an explicit baseline; it cannot be concealed as teacher preprocessing.
2. One-forward structured decision encoder (L07 first, L06 second): replace the GNN representation, emit all scheduling scores together, preserve the physical decoder. Single neural pass does not mean constant wall-clock time or pretrained reasoning automatically transfers.
3. Macro budget/communication controller (L04/L05): favor upgrades of critical/join-sensitive tasks with learned opportunity values. No extra per-step LLM calls; learned budgets are advisory and hard affordability is still exact. Requires an inexpensive numerical controller control.

Selecting a fixed rule is distinct from designing new rules. For an unchanged candidate set H, C_selected >= min_{h in H} C_h, pointwise. This is not a blanket comparison to our actual teacher, which replays mappings and runs local search rather than simply selecting native schedules.

Two-sentence pitch for the direct-policy hypothesis: Under limited upgrade budget, locally attractive EFT assignments can sacrifice future communication-critical or resource-critical tasks. A pretrained structured encoder might assign more globally consistent upgrade and placement scores in one pass; this is a falsifiable hypothesis, not established novelty or an observed advantage over the current GNN.

## Data and input/output contract

Reuse physical instances and graph-identity splits; create a new representation view rather than a new physical task. A canonical instance view contains:

- tasks:stable local ID,workload,resource demand; optional exact task-pool duration/cost/eligibility tables;
- dependency edges:parent,child,data volume; pool bandwidth matrix and local-transfer convention;
- pools:speed,cumulative capacity,execution price rate;
- budget:exact B,Bmin and normalized upgrade allowance;
- physical semantics:nonpreemption, fixed data/bandwidth lag, overlap convention, no link contention;
- derived features:critical-path/rank and branch summaries only if equally available to competing encoders.

Exact raw values remain available to the decoder and validator. Numerical normalization is deterministic per-instance or fit on TRAIN only. No precision loss may change budget feasibility. Serialize losslessly as compact records/JSON, or learn numerical feature embeddings; the latter is not automatically a better use of pretrained language knowledge. Avoid massive prose, dense adjacency matrices for sparse graphs, invented task semantics and lossy summaries that discard dependencies. No teacher solution appears in test inputs.

For strict-one-forward Qwen/Llama use, do not `generate()` a solution. Put the complete instance prefix first, then all known task/task-pool query positions. One model call yields hidden states for all query positions, each of which can attend to the complete prefix despite causal masking. Shared output heads predict a[i,p],w[i,p], and optionally task priority r[i]. An early task token in a causal model must not be assumed to see future task records. This query layout is a design proposal requiring implementation tests, context-length/padding/permutation audits and actual forward-call counters.

Compatible first output: same a,w arrays and same score range as the existing actor, same fixedHEFTorder decoder. Expanded output:priority r[i] plus a,w; the physical decoder selects among dependency-ready tasks, handles resource calendars and calculates start/end times. Hard budget and minimum remaining-cost reserve stay in the environment. One greedy construction only; no256sample or post-hoc hidden search. Optional upgraded opportunity-value functions may replace the budget term only in a separate controlled experiment.

## Supervision and RL

The present800trainingconfigs/36540expert actions can be converted into the new input view without regenerating assignment targets. This trains an action policy head, not ordinary assistant-text next-token SFT. First freeze the backbone and train heads, then consider adapter finetuning. Actual model/checkpoint/LoRA rank and available server must be specified before executing a pilot; none is chosen or downloaded here.

Current teacher action order is fixedHEFT. Copying it as an order target provides no evidence for learning better priorities. To train a new priority head, preserve feasible orders from native experts before forced replay, perform bounded joint order/mapping search on TRAIN, or let RL learn priorities without claiming novel order supervision. Validate targets through the same common physics. New order data must be supplied to GNN controls too.

RL uses actual environment makespan, not LLM-written reward or LLM-estimated duration. Define sampled categorical actions/conditional masks and their exact log probabilities; the static encoder is called once while the environment updates masks/EFT/reserve algebraically. A priority-output argmax alone is not a differentiable PPO objective. Frozen/adapted encoder, policy heads and optional value head need explicit trainable-parameter accounting. Keep the current teacher anchor and any changes isolated. A larger backbone does not repair sparse credit assignment by itself.

## Minimal test and stop rules

See [draft pilot](../experiments/llm_role_pilot/protocol.md). Before running large models, measure fixed-order mapping room and establish whether extended training improves current BC/PPO. First LLM study keeps information, teachers, masks, scoring range and decoder unchanged. Evaluate both BC and BC+PPO with >=3seeds, fixed validation selection and fresh graph-disjoint TEST, and all adapted baselines/teacher plus total runtime. Add a small Transformer and a matched pretraining ablation before attributing any gain to LLM pretraining.

If priority learning is introduced, compare GNN/LLM x fixed/learned-order under identical physics and labels; do not attribute an expanded solution space solely to the LLM. Report total parameters, trainable parameters, training samples/time, peak memory and end-to-end latency. Offline generated rules require frozen train/selection rules and the same full tests. Stop escalating model size if gains do not replicate or are matched by the simpler controller/encoder. No final novelty, result or publication claim is made.
